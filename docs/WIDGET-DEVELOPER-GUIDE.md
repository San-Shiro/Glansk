# Glansk Widget Developer & Architecture Guide

This document is the authoritative developer and architectural specification for building, packaging, and running widgets in the [Glansk](https://github.com/San-Shiro/Glansk) dashboard engine.

---

## 1. Architectural Foundation & Sandboxing Model

Glansk is engineered to run on low-resource embedded hardware (down to Raspberry Pi Zero 2 W with 512 MB RAM) as well as modern multi-screen fleet displays.

To ensure stability, memory containment, and strict multi-tenant security, all widgets execute inside an isolated browser iframe:

```html
<iframe
  class="widget-frame"
  sandbox="allow-scripts"
  src="/api/v1/packages/widgets/<pkg>/<widget>/index.html">
</iframe>
```

### Security Invariants

| Security Boundary | Policy & Implementation |
| :--- | :--- |
| **Iframe Sandbox** | Strictly `sandbox="allow-scripts"`. **NEVER** includes `allow-same-origin`. |
| **Origin Identity** | Opaque `null` origin. Widgets cannot access host DOM, parent cookies, or storage. |
| **Content Security Policy** | `default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'none';` |
| **Storage Confinement** | Native `localStorage`, `sessionStorage`, `document.cookie`, and `IndexedDB` throw `SecurityError: Access is denied for this document`. |
| **Network Confinement** | `connect-src 'none'` blocks all raw `window.fetch()` and `XMLHttpRequest` calls. |

## 2. Host Message Broker Protocol

Communication between the host and sandboxed widgets occurs exclusively via the HTML5 `postMessage` API using the `glansk.widget.v1` protocol.

```
┌─────────────────────────────────┐                 ┌─────────────────────────────────┐
│         Sandboxed Iframe        │                 │           Glansk Host           │
│                                 │                 │                                 │
│  Glansk.connect()               │ ── connect ───> │  Accepts message if:            │
│                                 │                 │  1. sourceWindow === iframe     │
│  Resolves with widget API <─────┼── connected ──  │  2. origin === "null"           │
│  (nonce, identity, config,      │                 │  3. protocol === "v1"           │
│   display, variables)           │                 │  4. payload <= 16 KB            │
│                                 │                 │  5. key <= 128 chars            │
│  widget.reportReady()           │ ─── ready ────> │  frame.dataset.ready = 'true'   │
└─────────────────────────────────┘                 └─────────────────────────────────┘
```

### Message Structure
Every message traveling between the iframe and the host carries:
```typescript
interface IdentifiedWidgetMessage {
  protocol: "glansk.widget.v1";
  instanceId: string;
  nonce: string;
  type: string;
  // ...type-specific payload
}
```

The `nonce` is a cryptographically random UUID generated by the host at render time and bound to that specific iframe instance. The host drops any message where the nonce, instance ID, or source window does not match.

## 3. The 3-Tier Storage Model

The **3-Tier Storage Model** eliminates configuration ceremony and allows widget authors to choose state retention **per element / feature** directly in code:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        3-Tier Storage Model                            │
├─────────┬───────────────────────────┬──────────────────────────────────┤
│ Tier    │ Scope & Lifecycle         │ SDK API                          │
├─────────┼───────────────────────────┼──────────────────────────────────┤
│ Tier 1  │ Ephemeral / Session       │ Plain JS: let count = 0;         │
│         │ Resets on reload          │ Zero SDK calls                   │
├─────────┼───────────────────────────┼──────────────────────────────────┤
│ Tier 2  │ Client-Scoped Storage     │ widget.storage.get(key)          │
│         │ Persists across reloads   │ widget.storage.set(key, val)     │
│         │ Resets in incognito/tabs  │ widget.storage.delete(key)       │
├─────────┼───────────────────────────┼──────────────────────────────────┤
│ Tier 3  │ Multi-Screen Shared State │ widget.shared.on(key, callback)  │
│         │ Real-time SSE sync (<1s)  │ widget.shared.set(key, val)      │
│         │ Durable disk persistence  │ widget.shared.get(key)           │
└─────────┴───────────────────────────┴──────────────────────────────────┘
```

### Tier 1: Ephemeral / Session State
- **Mechanism**: In-memory JavaScript variables (`let x = 0;`).
- **Lifecycle**: Preserved while the page is running; automatically reset to initial code values upon page refresh.
- **Latency**: Sub-microsecond (native CPU).
- **Use Cases**: Transient UI state, active accordions, temporary search filter inputs, scratch counters.
- **Cost**: Zero network, zero storage.

```javascript
let currentView = "overview";
let scratchpadText = "";
```

---

### Tier 2: Client-Scoped Storage (`widget.storage`)
- **Mechanism**: Brokered via `postMessage` (`storage-get`, `storage-set`, `storage-delete`) to the host, which reads/writes `/api/v1/interactive-state?mode=cookie`.
- **Attribution**: Scoped to the host's `gl_client_id` cookie.
- **Lifecycle**: Persists across browser reloads, navigation, and power cycles on the **same client device**. Resets if opened in an incognito window or on another device.
- **Bounds**: Key $\le 128$ characters; payload $\le 16\text{ KB}$.
- **Use Cases**: User personalizations, selected themes, dashboard density preferences, mute toggles.

```javascript
// Reading from Client Storage
const savedTheme = await widget.storage.get("ui_theme");
if (savedTheme) {
  document.body.className = savedTheme;
}

// Saving to Client Storage
themeDropdown.addEventListener("change", async (e) => {
  const theme = e.target.value;
  await widget.storage.set("ui_theme", theme);
});

// Deleting a key
await widget.storage.delete("ui_theme");
```

---

### Tier 3: Multi-Screen Shared State (`widget.shared`)
- **Mechanism**: Brokered via `shared-subscribe` and `shared-set`.
  - **Local Fan-Out**: 0ms immediate postMessage delivery to all other widget frames on the same canvas.
  - **Durable Disk Persistence**: Persisted to `/api/v1/interactive-state?mode=global` on server disk (`runtime/data/interactive-state.json`).
  - **Cross-Kiosk Fleet Broadcast**: Broadcasted to all connected kiosks, tablets, and operator windows via Server-Sent Events (`/api/v1/interactive-state/events`).
- **Lifecycle**: Universally persistent. Survived server restarts, page refreshes, incognito sessions, and device boundaries.
- **Latency**: 0ms local tile sync; $<800\text{ ms}$ global fleet sync.
- **Use Cases**: Turbine setpoints, factory machine overrides, global alert banners, shared shift handoff logs.

```javascript
// 1. Subscribe to real-time fleet updates
const unsubscribe = widget.shared.on("reactor_rpm", (rpm, meta) => {
  gauge.setValue(rpm);
  if (meta?.remote) {
    statusPill.textContent = `Synced from remote operator: ${meta.from}`;
  }
});

// 2. Read current cached value synchronously
const currentRpm = widget.shared.get("reactor_rpm");

// 3. Mutate shared state (updates local peers + fleet + disk)
setpointSlider.addEventListener("input", (e) => {
  const rpm = Number(e.target.value);
  widget.shared.set("reactor_rpm", rpm);
});
```

---

### Unified State Handle (`widget.state`)
The SDK provides a single convenience helper that normalizes all three tiers into a reactive signal:

```javascript
// Create a state handle
const rpm = widget.state("rpm", { scope: "shared", default: 50 });
const theme = widget.state("theme", { scope: "client", default: "solar-gold" });
const notes = widget.state("notes", { scope: "session", default: "" });

// Read value
console.log(rpm.get());

// Set value
rpm.set(75);

// Subscribe to mutations
const unwatch = rpm.subscribe((newVal) => {
  console.log("RPM updated to:", newVal);
});
```

## 4. Inter-Widget Pub/Sub Event Bus

Widgets can publish events to peer widgets without coupling to their identities:

```javascript
// Publisher Widget
widget.broadcast("reactor.scram", {
  active: true,
  timestamp: Date.now(),
  operator: "ControlRoom-A"
});

// Subscriber Widget
const unsub = widget.onNotification("reactor.scram", (payload) => {
  if (payload.active) {
    triggerAlarmBuzzer();
  }
});
```

## 5. Canvas Variables

Glansk canvases maintain reactive global variables (e.g. system operational modes, global timestamps, device status).

```javascript
// Read all variables on the canvas
const allVars = widget.getVariables();
console.log("Current status:", allVars["system.status"]);

// Mutate a canvas variable
widget.setVariable("system.status", "RUNNING");

// Listen for canvas variable changes
widget.onVariableChange((name, value, all) => {
  if (name === "system.status") {
    renderStatusBadge(value);
  }
});
```

## 6. Secure Egress Fetch & Secret Vault

Because sandboxed widgets have `connect-src 'none'`, they cannot make direct `fetch()` calls. All outbound network requests must be brokered through the host:

```javascript
const response = await widget.fetch("https://api.weather.gov/gridpoints/TOP/31,80/forecast", {
  method: "GET",
  headers: { "Accept": "application/json" },
  timeoutMs: 6000,
});

if (response.ok) {
  const data = await response.json();
  console.log("Temperature:", data.properties.periods[0].temperature);
}
```

### Secret Vault Injection
To connect to authenticated external APIs without leaking API tokens into the client bundle, use `{{secret:NAME}}` syntax:

```javascript
const res = await widget.fetch("https://api.datacenter.org/v1/metrics?key={{secret:DATACENTER_API_KEY}}", {
  headers: {
    "Authorization": "Bearer {{secret:ENTERPRISE_JWT}}"
  }
});
```
The Glansk backend server substitutes `{{secret:KEY}}` with the plaintext secret from its AES-GCM encrypted vault (`runtime/data/vault.key`) before transmitting the request to the upstream server. The secret is never returned to the sandboxed widget iframe.

## 7. Verification & Release Gates

Before releasing or updating a widget package:

1. **Unit Tests**: Run `bun test` (all 266+ contract tests must pass).
2. **Typecheck**: Run `bun run typecheck` (`tsc --noEmit` with zero diagnostics).
3. **Multi-Screen & Storage Verification**:
   Execute `node scripts/test-3tier-storage.cjs` to confirm:
   - Shared variables sync across independent browser contexts in $<800\text{ ms}$.
   - Client storage persists on reload but isolates across incognito sessions.
   - Ephemeral session variables reset cleanly to initial states.
4. **WPE Embedded Validation**:
   Run `scripts/target-wpe-gate.sh` to test sandbox enforcement and memory budget on the target Raspberry Pi Zero 2 W hardware.
